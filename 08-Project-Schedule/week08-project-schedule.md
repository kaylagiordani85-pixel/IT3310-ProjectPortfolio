### WBS Rationale

My WBS connects to my Week 5 project scope because it breaks down the work needed to implement a unified patient intake and scheduling system across all six RCHN clinics. I divided the project into planning, system development, testing, and implementation. Each section focuses on work that supports the overall project goal. I also included testing with Intake Coordinators because their feedback is important in making sure the new system addresses the problems they experienced with the old system. Employee training is another important part because staff will need to understand how to use the new system before implementation.

## Task Dependencies

- Develop employee training materials → Train clinic employees, Finish-to-Start 

- Configure patient intake workflows →Prepare employee training materials, Start-to-Start 

- Define patient intake and scheduling requirements → Develop project schedule, Finish-to-Start
  
### Dependency Logic

If the intake system takes longer than expected it could delay testing because the team needs the system to be ready before they can test it. This could also affect employee training and the implementation schedule. Since the new system needs to be implemented across all six clinics, a delay in one part of the project could affect when the other activities can begin.
