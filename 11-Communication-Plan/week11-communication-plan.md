**Owner:** Project Manager

**Method:** Push 

### Entry 4
**Stakeholder:** Clinic Intake Coordinators

**Information Needed:** Scheduling updates, intake requirements, testing progress, and unresolved issues.

**Timing / Trigger:** During workflow testing and implementation.

**Frequency:** Weekly

**Format:** Meeting

**Owner:** Project Manager 

**Method:** Interactive

### Entry 5
**Stakeholder:** IT Support Staff 

**Information Needed:** System updates, technical issues, testing results, and implementation progress.

**Timing / Trigger:** During system testing, implementation, and when technical issues occur.

**Frequency:** As-needed

**Format:** Dashboard

**Owner:** Product Manager

**Method:** Pull

### Communication Method Justification

I chose pull communication for the RCHN IT Support Staff because they need access to technical updates throughout the project. A real-time dashboard allows them to check system progress, testing results, and technical issues when needed without waiting for an email or meeting.

I chose push communication for the Board of Directors because they have high influence over the project and need regular updates about the budget, risks, and progress. Monthly executive summaries would help them stay informed without needing to attend every meeting.

## Escalation Path
Level 1: Product Manager handles issues that can be resolved at the team level. Triggered when a test shows that the intake and scheduling functions are not working together properly. Expected response time: Within 24 hours.

Level 2: Project Manager handles issues that could affect the project schedule or budget. Triggered when the Product Manager cannot resolve the issue and testing across the clinics may be delayed. Expected response time: Within 1 business day.

Level 3: Chief Medical Officer (CMO) handles issues requiring decisions from RCHN leadership. Triggered when the unresolved issue could delay implementation or affect clinic operations. Expected response time: Within 1 business day.

### Escalation Scenario
If Risk 3 from my Week 9 Risk Register occurred, the escalation would unfold as follows:

Step 1: The Product Manager would review the failed test and work with the team to fix the intake and scheduling functions.

Step 2: If the issue cannot be resolved within 24 hours, the Product Manager would escalate it to the Project Manager because it could delay testing across all six clinics.

Step 3: As Project Manager, I would review how the delay affects the project schedule and budget. If the issue could affect implementation across the clinics, I would escalate it to the Chief Medical Officer for a decision.

This process would help the team address the issue before moving forward with implementation.

## Gap Analysis
### Communication Gap

One gap in my communication plan is that it does not include a clear process for notifying all six clinics when the implementation schedule changes. This matters because delays could affect staff training and daily operations. To fix this, I would have the Project Manager send updates to Clinic Managers whenever major schedule changes occur.

### Silence as a Communication Decision
If the project team does not provide updates during system testing, Clinic Managers may assume the project is delayed even if everything is on schedule. My communication plan prevents this by providing weekly updates so stakeholders know the project's progress and upcoming activities.
